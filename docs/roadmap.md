# 实施路线

## 已实现的 MVP

- Android 11+ 开发者侧载客户端：无障碍节点树、按需 JPEG 截图、点击、滑动、输入、返回/主页、应用版本查询。
- 用户启动的前台会话通知、默认网络切换回调和主动重连。
- Go relay：设备主动 WSS 连接、断线自动重连、独立令牌、单设备串行操作、20 秒超时、Streamable HTTP MCP。
- Nginx + systemd 部署示例和模拟设备。Android 与服务端不使用无线 ADB 作为运行链路。

## 下一阶段：稳定性（约 2–4 人日）

HTTPS 扩展 v0.3.0 已增手机一次性口令、viewer/controller 会话、按需 JPEG、状态与元数据、有限动作、幂等回执、一次性只读分享链接、OpenAPI 和服务首页。控制只限手机指定的可调试 App，Back/Home 后转为只读。小米真机已通过只读、控制和口令自然过期闭环；更多系统版本仍按 [HTTPS API 说明](https-api.md) 继续验收。

- 已完成：小米实机后台设置排障、无障碍服务销毁后的重连清理、同 ID 新连接替换旧连接的回归测试；用户已开启的会话增加重启/更新后恢复入口。
- 待验收：新版 APK 在实机连续锁屏 30 分钟、移动网络切换、relay 重启、手机重启和安装更新后的恢复。
- 后续：按厂商扩展兼容矩阵、请求指标和日志脱敏；多设备配对和令牌轮换。

## 第三阶段：开源可用性（约 3–5 人日）

- 已完成：Go 与 Android CI 构建、调试 APK 构建产物、快速开始和贡献指南。
- 待完成：扫码配对、设备端服务器指纹、固定签名的正式 APK 与版本发布、更多 Android 系统和分辨率验证。
- 后续：公开兼容矩阵，按需加入本地 stdio 适配器。

## 第四阶段：圆伴悬浮球与高风险操作（约 5–10 人日）

- 卡通悬浮球第一版已在小米真机验收：可选显示、呼吸/眨眼、连接状态、拖动贴边、暂停/恢复和隐藏。暂停时 MCP 立即拒绝远程读屏与操作，恢复后截图和界面树重新可用；截图中不含悬浮球。
- 待完成：显示当前智能体会话、逐单确认与撤销入口。
- 为订单、支付等流程增加结构化草稿和手机端本地确认；确认绑定订单摘要、金额、商户和短时效。用户取消或超时即拒绝；敏感字段不经 MCP 返回。
- 提交后展示订单状态及平台允许的撤销/售后入口。无可撤销路径时，在最终确认前明确提示。

这些工作量是单人粗估。当前版本只用于开发测试，不具备支付或下单授权流程。
